# 포트폴리오 대시보드 — 기획서

> 이 문서가 작업 지시서입니다. `AGENTS.md`의 규칙을 먼저 읽고 시작하세요.
> 결과물 위치: `dashboard/index.html` (+ 필요 시 `dashboard/app.js`, `dashboard/style.css`)

---

## 1. 무엇을 만드는가

`portfolio.html`은 **채용 담당자에게 보여주는 화면**입니다.
대시보드는 **본인이 포트폴리오를 관리·점검하는 화면**입니다. 성격이 다릅니다.

| | 포트폴리오 페이지 | 대시보드 |
| :-- | :-- | :-- |
| 보는 사람 | 채용 담당자 | 이제준 본인 |
| 목적 | 설득 | 점검과 관리 |
| 읽는 방식 | 위에서 아래로 정독 | 훑어보고 문제를 찾음 |

**대시보드의 한 가지 일:** 지원 서류를 내기 전에, 포트폴리오에 빈 곳이나 어긋난 곳이 없는지 한 화면에서 확인한다.

## 3. 화면 구성

### 3-1. 상단 — 상태 요약

한 줄에 4개 타일. 계산값만 쓰고 지어내지 않습니다.

| 타일 | 계산 |
| :-- | :-- |
| 프로젝트 | `projects.length` (대표작 1건 포함) |
| 수치 지표 | `results[]`의 총 개수 |
| 기술 | `stack[].groups[].tech[]` 중복 제거 개수 |
| 점검 경고 | 4절 규칙 위반 건수 — 0이면 초록, 1건 이상이면 강조 |

### 3-2. 프로젝트 보드

프로젝트 5건을 카드로. 각 카드에 표시할 것:

- 제목 / 분류 / 기간
- 대표 지표 (`card.kpi` + `card.kpiNote`)
- **채움 상태 막대** — 아래 항목 중 몇 개가 채워졌는지: 역할, 기간, 사용 기술, 문제 서술, 해결 단계(1개 이상), 결과 수치(1개 이상), 이미지
- 비어 있는 항목은 회색 칩으로 무엇이 없는지 명시
- 대표작(`featured: true`)은 시각적으로 구분

카드 클릭 → 우측 패널(또는 모달)에 `sections[]` 전문. `ownWork: true` 섹션에는 **본인 담당** 배지.

### 3-3. 타임라인

`meta.기간` 또는 `category`에서 연월을 파싱해 2024.03 — 2025.12 구간에 가로 막대로. 프로젝트가 겹치는 구간이 드러나야 합니다.

### 3-4. 기술 스택 현황

Tier 1 / Tier 2 별로 기술 칩. 각 기술이 **실제로 어느 프로젝트에서 쓰였는지** `projects[].meta['사용 기술']`과 대조해 표시하고, **한 번도 안 쓰인 기술은 따로 묶어 보여줍니다.** (스택에는 적었는데 근거 프로젝트가 없는 항목 — 면접에서 가장 먼저 찔리는 곳)

### 3-5. 점검 결과

4절 규칙을 돌린 결과를 목록으로. 각 항목에 무엇을·어디서 고쳐야 하는지 표기.

## 4. 점검 규칙

대시보드가 자동으로 확인할 것:

1. **금지 표현** — `엔지니어`, `개발자`, `풀스택`, `프론트엔드 엔지니어`가 인물 서술(`role`, `lead`, `summary[].title`)에 있으면 경고
2. **학과** — `affiliation`에 `그린스마트시티`가 있으면 경고
3. **GitHub** — `contacts[]`에 `jejun-lee`(계정 404)가 있으면 경고
4. **빈 항목** — 프로젝트에 결과 수치가 없거나, 역할·기간·사용 기술이 비어 있으면 경고
5. **근거 없는 기술** — 스택에 있는데 어느 프로젝트에도 등장하지 않는 기술
6. **전화번호 노출** — `contacts[]`에 `tel:`이 있으면 정보(경고 아님)로 표시

- 모바일 400px에서 가로 스크롤 없음
