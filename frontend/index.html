자주 받는 질문

조경학과인데, 웹까지 직접 만들게 된 계기는 무엇인가요?

조경은 도시의 녹지와 경관, 사람이 머무는 공간을 다루는 학문이고, 그 판단의 근거는 결국 공간 데이터입니다. 학업을 진행하며 데이터와 알고리즘이 실제 시민들의 삶을 바꾸는 순간을 목격했고, 이를 사용자에게 가장 직관적이고 강력하게 전달하는 매개체가 바로 웹 플랫폼임을 깨달았습니다.

설계 패널 한 장에 분석부터 결과까지의 정보 위계를 짜는 일과, 화면 위에 복잡한 데이터를 배치하는 일은 같은 종류의 작업이었습니다. 전공에서 배운 GIS 공간 분석과 공간을 읽는 눈이 웹에서의 상태 관리와 대용량 데이터 시각화로 자연스럽게 이어졌고, 그 결과 두 영역을 같은 언어로 설명할 수 있게 되었습니다.

DevSync 프로젝트에서 왜 WebSocket과 CRDT를 선택했나요?

일반적인 HTTP 폴링이나 단순 소켓 브로드캐스트는 네트워크가 불안정할 때 동시 편집 시 최종 쓰기 승리(Last-Write-Wins)로 인해 다른 사용자의 작업 내용이 유실되는 치명적 결함이 있었습니다.

Google Docs와 같은 OT(Operational Transformation) 방식은 중앙 집중식 서버의 연산 부하가 크고 복잡도가 높았습니다. 반면 CRDT는 각 클라이언트가 독립적으로 연산하고 병합하더라도 수학적으로 동일한 최종 상태로 수렴한다는 확신이 있었기에, 가볍고 지연시간이 적은 P2P 성향의 실시간 협업 에디터를 구축할 수 있었습니다.

1992년 임야 · 농경지였던 부지가 증여를 통해 법인 학원 소유로 이전되었고, 1997년 건축이 시작됐으나 비리 · 채무 · 압류로 2017년 대학 설립이 무산됐습니다. 채무와 압류는 해제됐지만 건물은 그대로 방치되어 슬럼화가 진행됐습니다.

문제 정의

  1. 훼손된 자연. 학교 설립을 위한 절토 공사로 산림과 지형이 심각하게 훼손되고, 관리 부재와 장기간 방치로 기존 생태계와의 연결성이 낮습니다.
  2. 버려진 공간. 개교조차 하지 못한 건물에 자재가 방치되고 유리가 흩뿌려져 있으며, 관리 부재로 담력체험장으로 오용되며 위협감을 조성합니다.
  3. 낮은 접근성. 대상지로 접근할 수 있는 동선이 한정적이고, 그마저도 관리 부재로 도로가 파손된 상태입니다.

디자인 컨셉 — 세 번의 화답

버려진 경사지 부지를 공원으로 재생해 자연의 흐름을 회복하고, 카페와 전망대에서 경관을 바라보며 자연과 공간의 연결성을 느낄 수 있게 했습니다. 지역 환경과 폐부지가 새로운 가치로 되살아나고 자연과 인간, 공간과 자연, 인간과 공간이 서로 공존하는 '화답숲'을 제안합니다.

공간 구상

  1. Harmony I : The Palette. 봄의 순백과 신비로운 푸른 빛, 여름의 강렬한 붉은 에너지와 햇살의 노란 빛이 어우러지는 4가지 색채 테마 정원. 각 테마 공간의 교차점에 퍼걸러를 배치해 소통 및 휴게 공간을 제공합니다.
  2. Harmony II : The Flow. 경사진 지형을 활용하고 바람에 흩날리는 실새풀 식재로 바람의 흐름을 시각화했습니다. 그라스 군락을 가로지르는 산책로와 거리별 식재 높이 계획으로 자연에 몰입하는 공간을 만듭니다.
  3. Harmony III : The Canvas. 폐건물 부지에 랜드마크인 대형 갤러리 카페를 유치해 트인 조망과 함께 머무를 수 있는 공간을 조성하고, 인근 대학생을 위한 전시공간과 시민 참여형 프로그램으로 문화 플랫폼을 구축합니다.

프로그램 구성

  1. 식물 QR코드. 이국적 수종을 포함한 다양한 식재에 QR코드 팻말을 설치해 방문객이 상세 정보를 확인할 수 있게 한 스마트 생태 학습 프로그램입니다.
  2. 대학 졸업 전시회. 인근 대학생의 졸업 작품과 창작물을 소개해 예술 활동을 독려하는 문화 지원 프로그램입니다.
  3. 참여형 작품 제작. 건물 내 대형 캔버스를 배치해 방문객이 직접 그리고 전시하는 시민 참여형 예술 체험입니다.
  4. 조형물 찾기. 억새와 실새풀이 우거진 산책로에 숨겨진 조형물을 찾아 인증하는 미션 수행형 탐험 프로그램입니다.

문제

개발자들이 원격 회의나 코드 리뷰를 할 때 문서 공유 툴(Notion)과 코드 실행 환경(IDE · 온라인 컴파일러)이 분리되어 있어 잦은 화면 전환과 컨텍스트 손실이 발생했습니다. 그렇다고 단순 WebSocket 브로드캐스트로 붙이면 네트워크 지연 시 동시 입력이 충돌해 다른 사용자의 작업이 덮어씌워지는 치명적 한계가 있었습니다.

해결

  1. CRDT 기반 무충돌 동시성 제어. 중앙 서버 잠금(Lock) 방식 대신 P2P 분산 동기화가 가능한 CRDT 알고리즘을 도입하여 다중 사용자의 동시 타이핑 충돌을 수학적으로 무결하게 병합했습니다.
  2. WebSocket 회복 탄력성 확보. 주기적인 Heartbeat(Ping/Pong) 모니터링과 지수 백오프 기반 재연결 로직으로 불안정한 네트워크 환경에서도 세션을 유지했습니다.
  3. 메인 스레드 블로킹 방지. 실시간 마크다운 파싱 및 코드 하이라이팅 연산을 Web Worker로 오프로딩하여 타이핑 시 UI 프레임 드랍을 완전히 제거했습니다.
  4. 가상화 렌더링. 긴 문서 편집 시 DOM 노드 폭증을 막기 위해 뷰포트 내의 라인만 렌더링하는 Windowing 기법을 적용했습니다.

사용 기술

문제

도시 환경 연구 과정에서 수집되는 미기후 센서(미세먼지 · 온도 · 풍속)와 도심 녹지 지표 데이터가 대용량 시계열 형태로 누적되면서, 브라우저 대시보드 로딩 시 TTFB 4초를 넘는 심각한 병목이 발생했습니다.

해결

  1. 비동기 API 및 캐싱 계층 구축. FastAPI 비동기 엔드포인트와 인메모리 캐싱(TTL 기반) 파이프라인을 구축하여 반복적인 센서 집계 쿼리의 DB I/O 부하를 격리했습니다.
  2. GeoJSON 기반 멀티 레이어 시각화. 천안시 구역별 녹지 비율과 센서 수치를 히트맵 및 폴리곤 레이어로 렌더링하고, 줌 레벨에 따라 데이터 상세도를 동적으로 조절하는 LOD(Level of Detail) 알고리즘을 적용했습니다.
  3. 시계열 이상 징후 알림. 이동평균(Moving Average) 알고리즘을 적용하여 임계치 초과 시 담당자에게 즉각 시각적 경고를 발송하는 이상 감지 모듈을 구현했습니다.

결과

4.2s → 1.4s10만 건 이상 센서 로그 조회 시 초기 대시보드 렌더링 응답 시간 (65% 개선)

FlowTask

역할
1인 프론트엔드 구현 (외부 라이브러리 없이)
기간
2024.12 — 2025.03 (약 4개월)
사용 기술
Vanilla JavaScript (ES6+), HTML5 Drag & Drop API, LocalStorage API, Chart.js

문제

무거운 프레임워크나 드래그 라이브러리(react-beautiful-dnd 등)는 번들 크기가 크고 모바일 · 저사양 환경에서 프레임 드랍이 발생합니다. 또한 단순 체크리스트 방식의 To-Do는 '중요하지만 긴급하지 않은 일'을 간과하게 만드는 한계가 있었습니다.

해결

  1. 네이티브 드래그앤드롭 래퍼 구현. HTML5 표준 DnD API를 순수 JS 클래스로 캡슐화하고, requestAnimationFrame을 활용하여 드래그 중인 카드의 물리적 이동 궤적을 60fps로 매끄럽게 보간했습니다.
  2. 아이젠하워 4분면 자동 스코어링. 마감일(D-day)과 사용자 지정 중요도 가중치를 결합하여 카드가 위치해야 할 최적 칸반 컬럼을 실시간 추천하는 알고리즘을 탑재했습니다.
  3. 오프라인 퍼스트 트랜잭션 동기화. 브라우저 LocalStorage에 데이터 변경 이력을 이벤트 소싱(Event Sourcing) 형태로 기록하여 새로고침 시에도 100% 무결성을 보장했습니다.

결과

0KBDnD 라이브러리 번들 오버헤드, 완전 오프라인 지원
60fps복잡한 드래그 상황에서도 프레임 드랍 없는 네이티브 성능
